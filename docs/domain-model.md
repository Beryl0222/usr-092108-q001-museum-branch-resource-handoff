# 跨馆资源接力领域模型

大同市博物馆总馆公共教育部下辖九座分馆，每年举办 150 余场社教活动。同一件复制教具、同一位讲师、同一批运输能力会被不同场馆同时争用；带队老师预约"北魏服饰复原课"时，需要确认的是**哪座分馆、教具是否已到、无障碍名额、临时闭馆后的替代场次**，而不是活动介绍。

本文件定义跨馆资源接力服务的统一语言。所有状态变更都以 `contracts/domain.schema.json` 规定的事件信封落账，事件只追加、不改写。

## 1. 身份（各有稳定身份）

| 聚合 | aggregate_type | 身份要点 |
| --- | --- | --- |
| 馆藏对象 | `collection_resource` | 馆登记号，真品。借调受环境条件约束 |
| 可移动复制品 | `movable_replica` | 复制教具编号，可跨馆重复周转 |
| 数字内容 | `digital_content` | 数字资产号 + 版本，授权使用、可并发，不占运力 |
| 展陈版本 | `exhibit_version` | 展陈方案版本号 |
| 讲解版本 | `interpretation` | 讲解口径（解释）版本，独立于展陈发布与更替 |
| 场地环境 | `venue` / `venue_slot` | 分馆与具体档期；携带温湿度、无障碍、停用状态 |
| 讲师资历 | `educator` | 讲师工号 + 可授课程清单与资质有效期 |
| 课程材料 | `course_material` | 课程编码 + 材料版本（讲义、耗材清单） |
| 团体预约 | `group_booking` | 预约单号，绑定场次与团体属性 |
| 散客候补 | `waitlist_entry` | 候补条目号，按顺位晋升或过期 |
| 运输交接 | `transfer_order` | 运单编号，记录发货、迟延、交接、签收、关闭 |
| 活动反馈 | `activity_feedback` | 反馈编号，活动结束后归档，不回写场次 |
| 活动场次 | `program_session` | 档期编号，是以上资源汇流的中心聚合 |

身份一经 `*_REGISTERED` / `*_PUBLISHED` / `SESSION_OPENED` 确立不再改变；状态变化全部以后继事件表达。

## 2. 三类借调资源，条件不同

- **真品（authentic_object）**：只能调往环境达标的场地。`CONDITION_RECORDED` 持续记录温湿度；出现 `ENVIRONMENT_ALERT_RAISED` 时，真品预约被撤回并回库（`RESOURCE_QUARANTINED`），**同场的复制品与数字内容不受影响**。环境恢复需经 `ENVIRONMENT_CLEARED` + `RESOURCE_CLEARED` 才能再次借调。
- **复制品（replica）**：实体周转。一次运输未完成前不得被另一场地占用；到场后须签收查验，破损则隔离（`RESOURCE_QUARANTINED`，状态"待检查"），查验通过为 `RESOURCE_CLEARED`（"可再次使用"），归还以 `RESOURCE_RETURNED` 落账。
- **数字内容（digital）**：以授权并发，不占运输能力；场馆停用或实物迟延时可立即顶替，是异常重排的首选替代。

## 3. 异常只重排受影响资源

异常事件（`ENVIRONMENT_ALERT_RAISED`、`TRANSFER_DELAYED`、`VENUE_TAKEN_OUT_OF_SERVICE`）通过 `caused_by_event_id` 与后继重排动作相连。重排规则：

1. 沿运单/预约反查**只锁定受影响的资源与档期**，其余资源的预约、讲师安排原样保留。
2. 运输迟延：只重排该运单上的复制品，优先以备用复制品或数字内容顶替，不牵动其他场馆在途物资。
3. 场馆停用（含临时闭馆）：受影响场次整体迁移到替代场次（`SESSION_RELOCATED` → `replacement_session_id`），已确认预约与保障名额**平移不重抽**；无法平移的散客候补按原顺位进入新档期候补。
4. 每次重排必须能从替代事件经 `caused_by_event_id` 回溯到根因事件。

## 4. 保障名额不能被平均分配吞掉

场次开仓（`SESSION_OPENED`）时声明容量与两类**保障配额**：儿童团体席、无障碍（行动不便）席。`SESSION_QUOTA_PROTECTED` 登记受保护名额，其不变量：

- 保障名额只能被对应属性的团体预约占用；普通预约和候补晋升不得占用。
- 配额是"下限保留"而非"先到先得后的余数"：即使普通预约更早到达，保障名额也保留至保护截止时间。
- 场次迁移到替代场次时，保障名额随预约整体平移；替代场次必须有不少于原场次的保障容量，否则迁移被拒绝。
- 候补晋升（`WAITLIST_ENTRY_PROMOTED`）同样受配额校验。

## 5. 离线补报只认一次

分馆网络中断期间在本地登记的"开始 / 完成 / 归还"动作，恢复后补报。每条补报携带 `idempotency_key`（建议：`场次/运单 + 动作类型 + 本地序号`）：

- 同一 `idempotency_key` 全局只生效一次；重复投递丢弃并告警，绝不产生第二条事件、不重复推进状态。
- 开始、完成、归还分别各认一次：动作类型不同，键不同；同一动作重复补报不覆盖已有结果。
- 补报事件的 `occurred_at` 填写**动作实际发生时间**，落账时间另行记录在 payload，投影按实际发生时间归位。

## 6. 讲解更新不得改写历史

讲解内容（解释口径、展陈版本、课程材料）全部带版本：

- `INTERPRETATION_PUBLISHED` / `EXHIBIT_VERSION_PUBLISHED` / `COURSE_MATERIAL_PUBLISHED` 发布新版本，旧版本保留；`EXHIBIT_VERSION_SUPERSEDED` 只标记更替关系，不删除内容。
- 每场活动在开课前由 `SESSION_CONTENT_PINNED` **固化**当时采用的讲解版本、展陈版本与材料版本。
- 此后即便讲解更新，该场次的还原结果仍指向旧版本；新版只影响之后开仓且重新固化的场次。

## 7. 验收可还原内容

从任一 `program_session` 出发，沿事件流必须能还原：

- **物品**：真品/复制品/数字内容清单、各自预约与释放、运单全程（发货→迟延→交接→签收→关闭）、到场状态与归还。
- **人员**：指派讲师（`EDUCATOR_ASSIGNED`）及其当时资质、课程可授范围。
- **场地**：分馆、档期、环境告警与恢复、停用与替代场次。
- **异常交接**：根因事件 → 重排事件的因果链、顶替资源、候补与预约的去向。
- **内容**：该场次固化的讲解/展陈/材料版本。
- **反馈**：`FEEDBACK_RECORDED` 归档结果。

预约页面对带队老师的回答必须与现场一致：**分馆地点、教具是否已到（签收查验状态）、无障碍剩余名额、闭馆时的替代场次**——四项均直接由事件投影得到，不另行人工维护。

## 8. 资源流转状态（总馆视图）

总馆通过投影识别每件资源当前所处环节：

- `可预约`：在册、无未闭合预约、查验合格；
- `已预约`：`RESOURCE_RESERVED` 锁定到场次，未发货；
- `途中`：`TRANSFER_DISPATCHED` 之后、`TRANSFER_HANDED_OVER`/`TRANSFER_ACKNOWLEDGED` 之前（迟延运单单独标出）；
- `待检查`：已到场未签收，或查验发现异常被隔离；
- `使用中`：场次进行档期内、签收合格；
- `可再次使用`：归还并查验合格（`RESOURCE_RETURNED` + `RESOURCE_CLEARED`）。

## 9. 事件信封约定

沿用仓库现有信封：`event_id`、`event_type`、`aggregate_type`、`aggregate_id`、`occurred_at`、`version`、`summary`，新增均为可选取值/字段：

- `idempotency_key`：离线补报去重（见 §5）；
- `correlation_id`：同一场接力（含替代场次、相关调拨）串联；
- `caused_by_event_id`：异常→重排因果链（见 §3）；
- `payload`：事件特有内容（资源类别、场馆、场次、运单、名额、版本号等）。

同一聚合内 `version` 从 1 严格递增；事件经接收即不可变，更正只能追加后继事件（如补记、撤回、替代）。最小化读取：反馈与预约中的个人信息仅对完成职责所必需的角色开放。
